# Состояние проекта

Файл для того, чтобы подхватить работу с любого места. Секретов здесь нет.

---

## Что это

Телеграм-бот для перекупа в Краснодаре. Следит за новыми объявлениями на
Авито, копит историю цен, присылает лоты дешевле медианы рынка и отвечает
на вопросы по сделке.

Репозиторий: `alexmarakulin-lab/avito-perekup` (переименован из
`slabotochny-bot`), рабочая ветка `claude/avito-resale-products-52tdn5`,
открыт PR #1. Слияние в `main` не делалось.

Бот в Telegram: `@krd_perekup_bot`, отображаемое имя «Перекуп 23».

## Что работает

- Авито читается с сервера напрямую, без прокси — проверено, отдаёт 200
- Бот собирается и запускается, монитор и сторож связи стартуют
- Telegram доступен через прокси: `getMe` отвечает `200 OK`
- Одно сообщение от бота дошло — приветствие по `/start`
- 85 оффлайн-проверок в трёх файлах `test_*.py`, все зелёные

## Что не работает

**Авито не отдаёт выдачу этому серверу.** Проверено 06.08.2026 перебором:
из четырёх вариантов адреса три получили капчу Qrator (403 и 429), а
четвёртый — главную страницу вместо поиска. Главная приходит с кодом 200 и
почти полумегабайтом разметки, но объявлений в ней нет: это вежливая
разновидность заслона. Порядок такой: первому запросу подсовывают главную,
всем следующим показывают капчу.

Адрес поиска здесь ни при чём — три варианта до Авито просто не дошли.
Утром 05.08 с этого же сервера `curl` дважды получал настоящую выдачу
(990 КБ, 16 карточек). После примерно сорока обращений за час доступ
закрылся и к вечеру не вернулся.

Перебрано и отвергнуто: заголовки (набор бота единственный из четырёх, что
проходил), метка Qrator, рукопожатие Chrome через curl_cffi. Осталось
непроверенным: держать паузы в разы длиннее и ждать сутки; российский
прокси через `AVITO_PROXY`; другой сервер.


**Бот отвечает через раз или молчит часами.** Канал через прокси
нестабилен: соединение обрывается молча, опрос Telegram встаёт, при этом
ни ошибки, ни падения. Однажды бот молчал 11 часов подряд, счётчик
обращений к Telegram был нулевой.

Первый сторож эту беду не ловил. Библиотека держит два раздельных набора
соединений: одни для опроса `getUpdates`, другие для всего остального.
Ломается опрос, а сторож дёргал `get_me` — то есть проверял вторую линию,
слышал ответ и обнулял счётчик неудач. Отсюда и одиннадцать часов при
нулевом счётчике.

Переделан 06.08.2026: соединение для опроса собирается вручную классом
`WatchedRequest` и само отмечает время последнего ответа. Здоровый опрос
отвечает раз в десяток секунд; 180 секунд тишины — жёсткий выход, Docker
поднимает контейнер заново. Пороги правятся через `TELEGRAM_WATCHDOG_INTERVAL`
и `TELEGRAM_WATCHDOG_SILENCE`. В тестах есть прямая проверка, что сторож
приставлен именно к опросу, — приставить его не туда можно молча.

**Консультант по сделкам не отвечает.** Groq отдаёт `HTTP 403` на
`llama-3.3-70b-versatile`. Либо ключ отозван, либо Groq не пускает запросы
с российских адресов. На монитор находок не влияет, они работают порознь.

## Что осталось сделать

1. **Убедиться, что бот стабильно отвечает.** Если продолжит молчать —
   менять прокси: у proxys.io есть возврат, можно взять другую страну.
   Настройка нового занимает одну команду `bash proxy.sh`.
2. **Нажать кнопку «🔍 Проверить Авито»** — это единственная непроверенная
   часть замысла. Разбор выдачи писался по известной структуре, но на
   живой странице не испытывался. Если покажет ноль карточек — править
   селекторы в `avito_monitor.py`.
3. **Вписать `AVITO_OWNER_ID`** в `.env` (узнать командой `/myid` у бота).
   Пока пусто — боту ответит любой посторонний.
4. **Перевыпустить ключи.** Токен бота и ключ Groq несколько раз попадали
   в переписку и на скриншоты. Отзыв: `/revoke` у @BotFather, для Groq —
   удалить ключ в console.groq.com. Новые вписать в `.env`.
5. По желанию — включить монитор кнопкой «🟢 Включить».

## Грабли, на которые уже наступали

Все они решены, но если что-то похожее всплывёт — вот причины.

**SSH не подключается, `Connection closed by port 22`.** Адрес сервера под
фильтрацией ТСПУ. Не лечится настройками, только сменой IP или VNC.
Дополнительно на этом образе `ssh.service` не был в автозапуске, а в
Ubuntu 24.04 с ним конфликтует `ssh.socket` — отключается командой
`systemctl disable --now ssh.socket`.

**Docker Hub не открывается из России.** Базовый образ берётся с зеркала
Яндекса, это уже прописано в `Dockerfile`.

**`docker-compose` первой версии падает с `KeyError: ContainerConfig`.**
Ставится вторая: `apt install -y docker-compose-v2`, вызывается через
пробел — `docker compose`, а не `docker-compose`.

**Бот получал команды, но не отвечал, `TimedOut` на отправке.** Умолчания
библиотеки — 5 секунд, на медленном канале не хватает. Подняты до 30,
правится через `TELEGRAM_TIMEOUT`.

**`Unknown scheme for proxy URL socks5h://`.** curl различает `socks5` и
`socks5h`, библиотека внутри бота знает только `socks5://`. Схема
приводится автоматически, в двух местах.

**Бот вис на старте без единой ошибки.** Сервер разрешал
`api.telegram.org` в адрес IPv6, а IPv6 на нём не работает. Адрес закреплён
по IPv4 через `extra_hosts` в `docker-compose.yml`, значение берётся из
`TELEGRAM_IPV4` в `.env` (сейчас `149.154.166.110`).

**Разбор выдачи находил ноль карточек.** Три причины, все молчаливые,
разобраны 05–06.08.2026 и исправлены.

Данные выдачи переехали из `window.__initialData__` в
`window.__preloadedState__`, и лежат там не url-кодированной строкой, а
строкой с экранированными кавычками. Прежний шаблон брал текст «до
ближайшей кавычки» и обрывался на первой же `\"` — то есть не заработал бы
и после переименования. Ищутся оба имени, экранирование разбирается честно.

Бот просил у Авито сжатие `br`, а `httpx` умеет только `gzip` и `deflate`.
Ответь Авито в brotli — в тексте страницы оказался бы двоичный мусор, и
выглядело бы это как смена вёрстки, без единой ошибки в логах.

Главная страница вместо выдачи принималась за пустой рынок. Теперь
распознаётся по заголовку: у выдачи он всегда «Перфораторы купить в
Краснодаре», у главной обезличенный. Судить по отсутствию карточек нельзя —
честно пустая выдача выглядит так же, и это законный ответ.

**Метка Qrator терялась из-за одного типа данных.** Получив `httpx.Cookies`,
библиотека складывает новые метки в собственную копию, наружу они не
возвращаются. `CookieJar` она берёт по ссылке. Разница глазом не видна,
ошибок не вызывает, и повторные попытки молча шли с чистого листа.

**Git с сервера не забирается.** `github.com` и `raw.githubusercontent.com`
оба под фильтрацией, `SSL connection timeout` идёт сериями. Прокси делает
хуже — пять минут ожидания вместо мгновенного отказа. Работает цикл:
`until git pull; do sleep 3; done` — сам повторяет, пока не пробьётся,
обычно с первой-второй попытки.

**Команды в консоли не выполняются, в начале строки `>`.** Незакрытая
кавычка при вставке. Лечится `Ctrl+C`. Буфер VNC режет длинные строки, так
что команду длиннее полутора строк надо разбивать: сначала записать адрес
в переменную, потом отдельной строкой позвать `curl` с `"$U"`.

**В логах виден токен бота.** Строки `getMe` и `deleteWebhook` содержат его
целиком, `grep -v getUpdates` их не убирает. Отсеивать надо по
`api.telegram.org` — так уходят все обращения к Bot API разом.

**Вставленная команда попадает в вывод работающей программы.** Вставлять
можно только при чистом приглашении `root@...#`.

## Команды на каждый день

Все — из папки `~/avito-perekup` в окне VNC.

```bash
docker compose logs --tail 30 | grep -v api.telegram.org  # что происходит, без токена
docker compose logs --since 2m | grep -c getUpdates  # жив ли опрос: ~12 это норма, 0 - висит
docker compose ps                                    # состояние контейнера
docker compose restart                               # перезапустить
docker compose up -d --build                         # пересобрать после git pull
nano .env                                            # настройки; сохранить Ctrl+O, Enter, Ctrl+X
bash proxy.sh                                        # заново настроить прокси
git pull                                             # забрать свежий код (иногда нужно 2-3 попытки)
```

## Из чего состоит код

| Файл | Назначение |
|---|---|
| `avito_bot.py` | точка входа: команды, кнопки, доступ, сторож связи |
| `avito_monitor.py` | монитор Авито: запросы, разбор выдачи, база, статистика |
| `resale_expert.py` | консультант по сделкам через Groq, опирается на свою статистику |
| `check_avito.py` | проверка Авито из консоли, без Telegram: обычный запуск, `probe` — перебор заголовков, `urls` — сравнение адресов, `dump` — сохранить страницу и разобрать, что это |
| `proxy.sh` | настройка прокси одной командой |
| `setup.sh` | первичная установка на чистый сервер |
| `test_*.py` | 85 оффлайн-проверок, сеть не нужна |
| `AVITO.md` | подробное описание и развёртывание |

Настройки — переменные окружения в `.env`, список с пояснениями в
`.env.example`.
